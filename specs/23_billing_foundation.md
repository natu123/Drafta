## 3. 仕組み

### 3.1 全体

```
アプリ (静的なページ)                 Cloud Functions (asia-northeast1)            Stripe
  「Proにする」 ──呼び出し(ログイン必須)──▶ createCheckoutSession ──────────▶ Checkout (購入ページ)
  「契約を管理」 ──呼び出し(ログイン必須)──▶ createPortalSession ───────────▶ Customer Portal
                                         stripeWebhook ◀── 署名付きの通知 ──── 購入・更新・解約・支払失敗
  Proの状態を購読 ◀── Firestore ◀──── サーバーだけが書く
```

- 関数は第2世代, 東京 (asia-northeast1, Firestoreと同じ) に置きます. コードはリポジトリの`functions/` (TypeScript) に置き, アプリとは別にDeployします. Hostingだけを公開する今の手順 (`--only hosting`) は変えません.
- アプリは静的なページのままです. 購入と契約の管理はStripeの画面に任せ, カード情報はDraftaに一切来ません.

### 3.2 Proの状態の置き場

- `/users/{uid}/billing/subscription` (1つのドキュメント): `plan` ('pro' / 'free'), `status` (Stripeの契約の状態), `interval` ('month' / 'year'), `currentPeriodEnd`, `cancelAtPeriodEnd`, `updatedAt`, `sourceEventCreated` (反映した通知の時刻).
- ルール: 本人だけが読めて, 誰も書けません (書くのはAdmin SDKを使う関数だけ). 今のルールの最後の「それ以外はすべて拒否」はそのままです.
- StripeのCustomer IDと処理済みの通知のIDは, クライアントから読めない場所 (`/billingCustomers/{uid}`, `/stripeEvents/{eventId}`) に置きます.
- Proとみなす状態 (案): `active`と`trialing`. 支払いの失敗でStripeが再試行している間 (`past_due`) を猶予としてProに含めるかは未決です.

### 3.3 購入と契約の管理

- `createCheckoutSession` (呼び出し可能な関数, ログイン必須): 月払いか年払いかと通貨 (円またはドル) を受け取り, そのUIDのStripe Customerを作るか再利用して, 定期支払いのCheckout Sessionを作り, そのURLを返します. `client_reference_id`とメタデータにUIDを入れます. 価格のIDはサーバー側の設定で持ち, クライアントから金額を受け取りません. すでにProなら作りません.
- 購入後の戻り先 (例: `/app/?billing=done`) に着いただけではProにしません. Webhookで状態が書かれるのを, Firestoreの購読で待ちます.
- `createPortalSession` (同じくログイン必須): 支払方法の変更, 月払いと年払いの切り替え, 解約, 領収書の確認をStripeのCustomer Portalに任せ, そのURLを返します.

### 3.4 Webhook

- `stripeWebhook` (HTTP): 生の本文と署名ヘッダーでStripeの署名を検証し, 通らないものは捨てます.
- 扱う通知 (案): `checkout.session.completed` (CustomerとUIDを結ぶ), `customer.subscription.created` / `updated` / `deleted`, `invoice.payment_failed` (必要なら通知に使う).
- 二重の通知と順番の入れ替わり: 通知のIDを記録して二度処理しません. 状態は通知の中身ではなく, その時点でStripeから契約を取り直して書きます. 書くときはトランザクションで, 記録済みより古い通知では上書きしません.
- 失敗したときは500を返し, Stripeの再送に任せます. ログには顧客のメールやカード情報を出しません.

### 3.5 アプリの画面

- 設定の中に「Pro」の項目を置き, 状態 (無料 / Pro, 次の更新日, 解約予定), 「Proにする」(月払い・年払い), 「契約を管理」を出します. 画面の形はOptions Firstで別途決めます.
- Proの機能 (共有リンク, リマインダー) がそろうまで, この項目は本番では出しません.
- Proの機能を開くときは, 画面の表示だけでなく, サーバー側 (ルールや関数) でもProの状態を確かめます.

### 3.6 退会と解約

- アカウントを削除するときは, 契約も解約します (退会の機能を作るときに合わせて設計します).
- 解約後は支払済みの期間の終わりまでProを使えます (返金なし). 期間が終わると`customer.subscription.deleted`で無料に戻ります.

## 4. 法務と表示

- 特定商取引法に基づく表記, 利用規約, プライバシーポリシーを, Proの開始前にWebで公開します (05のM4).
- 定期購入では, 申し込みの最終確認の画面に, 価格, 支払の時期と方法, 契約の期間と自動更新, 解約の方法を分かりやすく出す必要があります. StripeのCheckoutの画面だけで満たせるか (表示する文言の追加, 同意の欄) を, 導入時に確認します.
- プライバシーポリシーには, 支払の処理をStripeに任せること, Draftaが保存するのは契約の状態だけでカード情報は持たないことを書きます.
