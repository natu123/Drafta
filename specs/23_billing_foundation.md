## 3. 仕組み

### 3.1 全体

```
アプリ (静的なページ)                 Cloud Functions (asia-northeast1)            Stripe
  「Proにする」 ──呼び出し(ログイン必須)──▶ createCheckoutSession ──────────▶ Checkout (購入ページ)
  「契約を管理」 ──呼び出し(ログイン必須)──▶ createPortalSession ───────────▶ Customer Portal
                                         stripeWebhook ◀── 署名付きの通知 ──── 購入・更新・解約・支払失敗
  Proの状態を購読 ◀── Firestore ◀──── サーバーだけが書く
```

- 関数は第2世代, 東京 (asia-northeast1, Firestoreと同じ) に置きます. コードはリポジトリの`functions/` (TypeScript) に置き, アプリとは別にDeployします. Hostingだけを公開する今の手順 (`--only hosting`) は変えません.
- アプリは静的なページのままです. 購入と契約の管理はStripeの画面に任せ, カード情報はDraftaに一切来ません.

### 3.2 Proの状態の置き場

- `/users/{uid}/billing/subscription` (1つのドキュメント): `plan` ('pro' / 'free'), `status` (Stripeの契約の状態), `interval` ('month' / 'year'), `currentPeriodEnd`, `cancelAtPeriodEnd`, `updatedAt`, `sourceEventCreated` (反映した通知の時刻).
- ルール: 本人だけが読めて, 誰も書けません (書くのはAdmin SDKを使う関数だけ). 今のルールの最後の「それ以外はすべて拒否」はそのままです.
- StripeのCustomer IDと処理済みの通知のIDは, クライアントから読めない場所 (`/billingCustomers/{uid}`, `/stripeEvents/{eventId}`) に置きます.
- Proとみなす状態: `active`, `trialing`, `past_due` (6章で決定). 支払いの失敗でStripeが再試行している間 (`past_due`) は, 猶予としてProのままにします. 再試行はStripeのSmart Retriesと支払失敗の自動メールに任せ, 再試行が尽きたら解約する設定にします (Dashboard). 解約は`customer.subscription.deleted`で届き, 無料に戻ります.

### 3.3 購入と契約の管理

- `createCheckoutSession` (呼び出し可能な関数, ログイン必須): 月払いか年払いかを受け取り (通貨は受け取りません. 6章), そのUIDのStripe Customerを作るか再利用して, 定期支払いのCheckout Sessionを作り, そのURLを返します. `client_reference_id`とメタデータにUIDを入れます. 価格のIDはサーバー側の設定で持ち, クライアントから金額を受け取りません. すでにProなら作りません.
- Managed Payments を使います (6章の税の (d), 2026-10-29に決定): Checkout Sessionに`managed_payments[enabled]=true`を付け, 商品にはManaged Paymentsの対象の税コード (例: `txcd_10103000`, SaaSの個人向け) を付けます. APIのバージョンは`2025-03-31.basil`以降です. この場合, サブスクはCheckoutか決済用リンクからしか作れず, `subscription.default_payment_method`はAPIから変えられません (変更はCustomer PortalかLinkのサイトで行います). サブスクの課金の方式は, Stripeの推奨の flexible billing mode にします. 価格は円だけで作り, 税込み (`tax_behavior: inclusive`) にします (6章).
- 購入後の戻り先 (例: `/app/?billing=done`) に着いただけではProにしません. Webhookで状態が書かれるのを, Firestoreの購読で待ちます.
- `createPortalSession` (同じくログイン必須): 支払方法の変更, 月払いと年払いの切り替え, 解約, 領収書の確認をStripeのCustomer Portalに任せ, そのURLを返します.

### 3.4 Webhook

- `stripeWebhook` (HTTP): 生の本文と署名ヘッダーでStripeの署名を検証し, 通らないものは捨てます.
- 扱う通知 (案): `checkout.session.completed` (CustomerとUIDを結ぶ), `customer.subscription.created` / `updated` / `deleted`, `invoice.payment_failed` (必要なら通知に使う).
- 二重の通知と順番の入れ替わり: 通知のIDを記録して二度処理しません. 状態は通知の中身ではなく, その時点でStripeから契約を取り直して書きます. 書くときはトランザクションで, 記録済みより古い通知では上書きしません.
- 失敗したときは500を返し, Stripeの再送に任せます. ログには顧客のメールやカード情報を出しません.

### 3.5 アプリの画面

- **決定 (2026-10-29, Glesさん)**: 設定ではなく, 右上のアカウントのメニューに置きます. Options Firstで3案 (設定は1行と専用の画面・設定の中にすべて・アカウントのメニュー) を示し, Glesさんが「アカウントのメニュー」を選びました. 無料の人には「✨ Proにする」を出し, 押すと月払い・年払いを選ぶ小さな画面が開き, 選ぶとStripeの購入ページへ移ります. Proの人には「✨ Pro・(次の更新日, または解約の日) まで」と「契約を管理」を出します. 特典の短い説明は, その小さな画面に載せます. 設定の画面は変えません (0.10.4の, スクロールなしで収まる形を保つ).
- Proの機能 (共有リンク, リマインダー) がそろうまで, この項目は本番では出しません.
- Proの機能を開くときは, 画面の表示だけでなく, サーバー側 (ルールや関数) でもProの状態を確かめます.

### 3.6 退会と解約

- アカウントを削除するときは, 契約も解約します (退会の機能を作るときに合わせて設計します).
- 解約後は支払済みの期間の終わりまでProを使えます (返金なし). 期間が終わると`customer.subscription.deleted`で無料に戻ります.
- Managed Paymentsを使う場合, 「返金なし」でも, Stripeが購入から60日以内なら返金することがあります. Stripeからの問い合わせに48時間答えないと, 承認なしで返金されることもあり, 地域ごとのクーリングオフもStripeが適用します. Dashboardのサポート用のメールアドレスを最新に保ちます. また, 顧客がLinkにデータの削除を求めると, Stripeがサブスクを解約するので, その解約も同じ通知 (`customer.subscription.deleted`) で無料に戻します.

## 4. 法務と表示

- 特定商取引法に基づく表記, 利用規約, プライバシーポリシーを, Proの開始前にWebで公開します (05のM4).
- 定期購入では, 申し込みの最終確認の画面に, 価格, 支払の時期と方法, 契約の期間と自動更新, 解約の方法を分かりやすく出す必要があります. StripeのCheckoutの画面だけで満たせるか (表示する文言の追加, 同意の欄) を, 導入時に確認します. Managed Paymentsでは, 決済画面の下部に定型の支払条件が出て, 利用規約とプライバシーポリシーのリンクはCheckoutの設定で足せます. 売り手としてLinkが表示されるので, 特定商取引法の表記との関係も合わせて確かめます.
- プライバシーポリシーには, 支払の処理をStripeに任せること, Draftaが保存するのは契約の状態だけでカード情報は持たないことを書きます.

### 費用の目安 (導入時に再確認)

- Cloud Functions: 呼び出しは購入・管理・Webhookだけで, 無料枠の中に収まる見込みです.
- Secret Manager: 秘密情報2つで, 月に数十円程度の見込みです.
- Stripe: 日本のカード決済で3.6%前後. 固定の月額はかかりません. サブスクにはBillingの手数料 (課金額の0.7%) が加わり, 合わせて約4.3%です. Stripe Taxを使う場合は, 税の登録をした地域の取引ごとに0.5%が加わります. Managed Paymentsを使う場合は, 成功した取引ごとに3.5%が上乗せされ, 合わせて約7.8%です (Billingの0.7%がManaged Paymentsにも掛かる前提. 2026-10-29に料金のページで確認).

Proの開始前に, Stripe Taxの費用, 登録が必要な国と時期 (EUの非EU事業者向けの一括申告の仕組み, 英国など), 申告の手間を調べて示し, (c) と比べたうえで確定します.
  - **(d) Managed Payments の追加 (2026-10-29, 確認)**: Stripeの初期設定で「デジタル販売を簡素化 (Managed Payments)」を選んでいます. これはStripe (Link) が売り手として記録される形で, (b) ではなく (c) にあたります. 公式文書では, 海外の80ヶ国以上 (EU, 英国, 米国など) の顧客への販売は, Stripeが税の計算, 徴収, 登録, 申告, 納付まで行います. ただし, **日本に拠点がある事業者の国内の販売 (日本の顧客) は対象外**で, 消費税の扱いは自分で行います. 対象外の国への販売はStripe Taxで扱います (Managed Paymentsと一緒に使える税の仕組みはStripe Taxだけ). 手数料は3.5%の上乗せで, Billingを含めて約7.8%です (5章). 国内の消費税はどの案でも残るので, 税理士さんへの確認は変わりません. 確定の前に, (b) と (d) を, 手数料, 登録と申告の手間, 返金の扱い (3.6) で比べます. Managed Paymentsがアカウントで有効になっているかは, Dashboardの設定画面で確かめます (APIからは見えません).
