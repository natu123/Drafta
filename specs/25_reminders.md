[22_monetization_plan.md](22_monetization_plan.md)の「作る順番」の3段目です. メモに日時を付け, その時刻に通知を届けます. Pro (課金の基盤は[23_billing_foundation.md](23_billing_foundation.md)) の機能です. Firestoreルールの変更, 定期実行の仕組み, 秘密情報, 本番への公開は, 着手する段ごとに 内容・影響・リスクを示して明示承認を得ます (AGENTS.md). 通知の仕様 (特にiPhone) は設計時の理解で, 作るときに公式文書で確かめ直します.

| 決めごと | 選択 | 内容 |

## 2. 仕組み

### 2.1 置き場

サーバーが時刻の来たものを探せるよう, メモの本体とは別に置きます.

`reminders/{reminderId}` (`reminderId` = `{uid}_{noteId}`):

| 項目 | 内容 |
|---|---|
| `ownerUid`, `noteId` | 持ち主とメモ. 変更できません |
| `title` | 通知に出すメモのタイトル (保存のたびに追従. 共有リンクの写しと同じ流れ) |
| `wallTime` | 持ち主が選んだ現地の日時 (`2026-10-30T18:00`) |
| `timeZone` | 選んだときの端末のタイムゾーン (`Asia/Tokyo` など) |
| `repeat` | `none` / `daily` / `weekdays` / `weekly` / `monthly` |
| `nextAt` | 次に送る時刻 (UTC). `wallTime`と`timeZone`から計算します. 夏時間で存在しない時刻は直後の時刻にします |
| `active` | 完了・ゴミ箱・解除で `false` |

`users/{uid}/pushSubscriptions/{id}`: 端末ごとの通知の宛先 (Web Pushの`endpoint`と鍵). 本人だけが書けます.

### 2.2 送る仕組み

- Cloud Functionsの定期実行 (`onSchedule`, 1分ごと, asia-northeast1) が, `active == true` かつ `nextAt <= 今` のものを読みます.
- 持ち主が今Proか (`users/{uid}/billing/subscription`) を確かめ, Proなら持ち主の全端末へ送ります. Proでなければ送らず, 時刻だけ進めます (解約中は鳴らない. 再加入で次の回から鳴る).
- 送ったら, 繰り返しは次の`nextAt`へ進め, 繰り返しなしは`active = false`にします. 二重に送らないよう, 進める処理はトランザクションで行います.
- 送り先が無効 (端末で許可を取り消した, 410 Gone) なら, その宛先を消します.
- 送る処理の署名にはVAPIDの鍵を使い, 秘密の鍵はSecret Managerに置きます.
- 遅れ: 定期実行は1分ごとのため, 最大で1分ほど遅れることがあります.

### 2.3 アプリの側

- 鈴の小窓で日時を決めると, クライアントが `reminders/{uid}_{noteId}` を書きます (ルールでPro・本人・形を確かめます). 最初の1回だけ, 通知の許可を求め, 宛先を登録します.
- メモの保存のあと (共有リンクと同じ`afterSave`の流れ), リマインダーのあるメモの タイトルの変更・完了・ゴミ箱を反映します. 保存は待たせません.
- 通知の受け口として, 通知だけを扱う小さなService Worker (`public/sw.js`) を足します. ページのキャッシュはしません (今の動きを変えないため). 通知を押すと `/app/` でそのメモを開きます.
- 期限が過ぎたメモは, アプリの中でも一覧の日時を色で示します.

### 2.4 通知の内容

- 見出しはメモのタイトル, 本文は「Draftaのリマインダー」程度にします. メモの本文は送りません.
- ロック画面にタイトルが出ます. タイトルを隠す設定を付けるかは未決です.

## 3. メモの操作との関係

| 操作 | リマインダー |
|---|---|
| 完了にする | 止めます (`active = false`). 完了を外しても自動では戻しません |
| ゴミ箱へ移す・完全に削除 | 消します |
| 保存履歴から戻す・複製 | 付いてきません |
| 書き出し・取り込み | 含めません (メモの情報の外にあるため) |

## 4. 承認が必要な項目

| 項目 | 内容 | 主なリスク |
|---|---|---|
| R1. Firestoreルールの変更 | `reminders` と `pushSubscriptions` を足します | 他人のリマインダーや宛先を読み書きできてしまう. ルールのテストで防ぎます |
| R2. 定期実行 | Cloud Scheduler (1分ごと) と関数の公開. Blaze (A1) が前提です | 1分ごとの実行で費用が出る (月4万回余り. 無料枠の範囲と見込みますが, 作るときに確かめます) |
| R3. VAPIDの秘密の鍵 | Secret Managerに置きます | 漏れると通知を偽れる. リポジトリ・ログ・チャットに出しません |
| R4. Service Worker | 全ページに関わる仕組みを初めて入れます | 誤ると更新が届かない. 通知だけを扱い, キャッシュしない形に限ります |
