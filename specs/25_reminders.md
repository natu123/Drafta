## 2. 仕組み

### 2.1 置き場

サーバーが時刻の来たものを探せるよう, メモの本体とは別に置きます.

`reminders/{reminderId}` (`reminderId` = `{uid}_{noteId}`):

| 項目 | 内容 |
|---|---|
| `ownerUid`, `noteId` | 持ち主とメモ. 変更できません |
| `title` | 通知に出すメモのタイトル (保存のたびに追従. 共有リンクの写しと同じ流れ) |
| `wallTime` | 持ち主が選んだ現地の日時 (`2026-10-30T18:00`) |
| `timeZone` | 選んだときの端末のタイムゾーン (`Asia/Tokyo` など) |
| `repeat` | `none` / `daily` / `weekdays` / `weekly` / `monthly` |
| `nextAt` | 次に送る時刻 (UTC). `wallTime`と`timeZone`から計算します. 止まっているときは `null` (完了・解除・繰り返しなしで鳴り終えた) |
| `lang` | 通知の文言の言語 (設定したときの表示の言語) |
| `updatedAt` | サーバーの時刻 |

時刻の決め方 (`functions/src/reminder-time.ts`): 夏時間で存在しない時刻は, 飛んだ分だけ後ろへずらします (2:30は3:30. カレンダーのアプリと同じ). 2回ある時刻は1回目に鳴らします. 繰り返しは選んだ日から始め, それより前には鳴らしません. D1で, 止まった状態を `active` ではなく `nextAt` の `null` で表すことにしました. サーバーの検索が `nextAt <= 今` の1条件で済み, 複合インデックスが要らないためです.

`users/{uid}/pushSubscriptions/{id}`: 端末ごとの通知の宛先 (Web Pushの`endpoint`と鍵). 本人だけが書けます.

### 2.2 送る仕組み

- Cloud Functionsの定期実行 (`sendReminders`, `onSchedule`, 1分ごと, asia-northeast1) が, `nextAt <= 今` のものを古い順に最大200件読みます. 残りは次の1分に回ります.
- 持ち主が今Proか (`users/{uid}/billing/subscription`) を確かめ, Proなら持ち主の全端末へ送ります. Proでなければ送らず, 時刻だけ進めます (解約中は鳴らない. 再加入で次の回から鳴る).
- 送る前に, 繰り返しは次の`nextAt`へ進め, 繰り返しなしは`null`にします. この処理をトランザクションで行うため, 2つの実行が重なっても1回しか送りません. 先に進めてから送るので, 送る途中で失敗した回は送り直しません (多くても1回).
- 止まっていた間に過ぎた回は, まとめて1回だけ鳴らし, 次は未来の回にします.
- 送り先が無効 (端末で許可を取り消した, 410 Gone) なら, その宛先を消します.
- 送る処理の署名にはVAPIDの鍵を使い, 秘密の鍵はSecret Managerに置きます.
- 遅れ: 定期実行は1分ごとのため, 最大で1分ほど遅れることがあります.

### 2.3 アプリの側

- 鈴の小窓で日時を決めると, クライアントが `reminders/{uid}_{noteId}` を書きます (ルールでPro・本人・形を確かめます). 止める (`nextAt`を`null`にする) ことと消すことは, Proでなくてもできます. 最初の1回だけ, 通知の許可を求め, 宛先を登録します. 次の時刻の計算は, D2でクライアントからも同じものを使えるようにします.
- メモの保存のあと (共有リンクと同じ`afterSave`の流れ), リマインダーのあるメモの タイトルの変更・完了・ゴミ箱を反映します. 保存は待たせません.
- 通知の受け口として, 通知だけを扱う小さなService Worker (`public/sw.js`) を足します. ページのキャッシュはしません (今の動きを変えないため). 通知を押すと `/app/` でそのメモを開きます.
- 期限が過ぎたメモは, アプリの中でも一覧の日時を色で示します.

### 2.4 通知の内容

- 見出しはメモのタイトル, 本文は「Draftaのリマインダー」程度にします. メモの本文は送りません.
- ロック画面にタイトルが出ます. タイトルを隠す設定を付けるかは未決です.

## 3. メモの操作との関係

| 操作 | リマインダー |
|---|---|
| 完了にする | 止めます (`nextAt = null`). 完了を外しても自動では戻しません |
| ゴミ箱へ移す・完全に削除 | 消します |
| 保存履歴から戻す・複製 | 付いてきません |
| 書き出し・取り込み | 含めません (メモの情報の外にあるため) |

### D1の結果 (2026-10-30)

作ったもの:
- ルール: `reminders` と `users/{uid}/pushSubscriptions` (`Drafta_Web/firestore.rules`). 本番へは出していません (R1).
- 次の時刻の計算: `functions/src/reminder-time.ts`
- 送る処理: `functions/src/reminders.ts`. 暗号化と署名は `functions/src/push.ts` で, web-push 3.6.7 を使います.
- 定期実行の関数: `sendReminders` (`functions/src/index.ts`). 本番へは出していません (R2).
- 手元のEmulator用のVAPIDの鍵: 公開鍵と送り主は `functions/.env.local`, 秘密の鍵は `functions/.secret.local` です. どちらもGitの対象外で, 鍵の値は画面にもログにも出していません. 本番の鍵は, D4でGlesさんがSecret Managerへ入れます (R3).

確かめたこと:
- 時刻の計算の単体7件: 日付と時刻の読み取り, 1回だけ, 毎日・平日・毎週・毎月, 月末とうるう年, 夏時間をまたぐ, 飛ぶ時刻と2回ある時刻, 読めない値.
- 通知の要求の単体1件: 暗号化 (aes128gcm) とVAPIDの署名. タイトルは暗号文にしか入りません.
- 空のEmulatorで送る処理5件: Proの持ち主の全端末に送り次の回へ進む, 繰り返しなしは鳴ったら止まる, 未来と止まったものは触らない, Proでなければ鳴らさず進む, 無効になった端末を消す, 過ぎた回は1回だけで2つの実行が重なっても1回.
- ルールのテスト12件 (リマインダーと宛先の2件を追加). Proでないと日時を付けられないが, 止める・消すはできる. 他人は読めず書けない. 形の誤りは拒否.
- アプリの単体452件と型, Lint.

Emulatorでは, 定期実行の関数は時刻で動きません (Pub/SubのEmulatorを使わないため). 中身の処理をテストから直接呼んで確かめました. 実際の端末へ届くかは D3 で確かめます.
