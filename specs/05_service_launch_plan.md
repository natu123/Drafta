# Drafta 正式サービス化: 着手時点の整理

確認日: 2026-09-15.

この文書は現状監査と段階計画です. 未承認の提案は既存仕様を上書きしません. 正式公開・課金開始・クラウド設定変更の承認書ではありません.

## 1. 確認できた現状

- Web UIはFirebase Hostingで公開しています.
- メモとトレイはReactのメモリ上で管理しています. リロード後の保存・復元を保証する実装はありません.
- 言語など一部設定の保存と、メモデータの永続保存は別です.
- package.jsonにFirebaseクライアントSDK・Stripe SDKはありません.
- `firebase apps:list --project drafta-memo --json`の結果は空配列でした.
- Firestoreデータベース一覧の取得は403で、API未使用または無効という応答でした. データベースの有無や実際のリージョンは確認できていません. APIは有効化していません.
- リポジトリにはFirestore/Storageのルールとエミュレーター構成がありません.
- コードはMITライセンスで公開されています. 公開範囲は変更していません.

## 3. 推奨する段階とコミット境界

### M0: リリース範囲と環境の確定

- 承認済み (2026-09-15): Web版を先行し、広告なしの無料ベータで保存と同期を検証してから有料化します.
- 承認済み (2026-09-15): 初期範囲はGoogleログイン先行とし、Appleログインは後続段階で扱います.
- 提案: 検証と本番でFirebaseプロジェクトを分離します. 新規プロジェクト名・管理アカウント・費用・リージョンは作成前に確認します.
- 完了条件: 提供範囲・認証方式・環境の方針が承認されています.
- コミット境界: 仕様確定文書を単独で記録します.

### M1: データ形式とバックアップ

- メモ・トレイ・設定の永続形式とスキーマバージョンを定義します.
- 現在のHTMLとDrafta-MDをTipTap JSONへ変換し、表・色・リスト・タイトルを往復試験します.
- ID・手動順・完了状態・削除状態・未命名・編集済みサンプルの扱いを保持します.
- エクスポートと検証付き復元を用意します. 復元前に重複・不正データ・HTML安全性を検査し、既存データを無断で上書きしません.
- 完了条件: バックアップからの復元で内容と構造の一致をテストできています.
- コミット境界: データモデル、変換と検証、バックアップUIを論理目的ごとに分けます.

#### M1の進捗

- 基盤実装済み: エディターと保存用変換処理のスキーマを共有し、文書単位のHTML↔TipTap JSON変換と往復テストを追加しました. 11言語×9サンプルの往復を含むテスト103件が成功しています.
- 基盤実装済み: ワークスペース全体のJSONバックアップ形式、型・属性・URL・参照・件数上限の検証、既存IDの衝突確認を追加しました. 既存状態へ書き込まない復元候補を返します. 詳細は`07_workspace_backup.md`です.
- 未完: ファイル選択・ダウンロードと復元UI、JSONからアプリ状態への適用、実際の永続保存です. M1全体が完了したわけではありません.
- 文書変換器は内部データ向けです. 任意の外部JSON/HTMLの安全性を保証するサニタイザーではなく、インポート機能として公開しません.

### M2: 認証と保存

- ローカルエミュレーターで認証・Firestore Rules・所有者分離を検証します.
- 認証状態が確定する前に初期サンプルをクラウドへ保存しません. 他ユーザーへのデータ混入とサインアウト時の残存表示を防ぎます.
- 保存は専用のデータアクセス層に集約します. UIへFirestore呼び出しを分散させません.
- サーバー確認後だけ保存済みと表示し、失敗・再試行・未保存状態を明示します.
- 別アカウントの読取/更新拒否、再ログイン、リロード、通信断、保存中の画面切替を試験します.
- 完了条件: 所有者だけがアクセスでき、保存確認後の再読み込みで内容を復元できます.
- コミット境界: SDK接続、認証、ルールとテスト、保存層、保存状態UIを分けます.

### M3: 同期・容量・運用

- 複数端末で同じメモを同時編集した場合の競合方針を決め、片方の変更を黙って失わないようにします.
- Firestoreの1ドキュメント上限を踏まえ、メモ単体のサイズ上限と容量計算を設計します. プラン総容量とは別に扱います.
- 画像の認可・サイズ・形式検証と、保存失敗時の孤立ファイル処理を設計します.
- 保存失敗率・同期遅延・利用量・費用を観測し、バックアップ復元手順を実際に試します.
- 完了条件: 複数端末・競合・障害復旧・容量境界の試験が成功しています.

### M4: 有料化と正式公開

- 決済案はStripe Billing + Checkout、契約管理はCustomer Portalとします. 採用と公開前に現行公式仕様を確認します.
- 支払成功ページへの到達だけでPro権限を付与しません. サーバー側で署名検証済みWebhookと契約状態を処理し、重複・順序逆転・再送を扱います.
- 料金・容量・解約・失敗時の権限・返金運用を確定し、テストモードで購入から解約まで検証します.
- 利用規約・プライバシー表示・解約/退会・データ削除/書き出し・問い合わせ先をWeb公開前に整えます. ストア申請時まで先送りしません.
- 実課金・本番データ保存・本番設定変更・正式告知はそれぞれ明示承認後に行います.
- 完了条件: 無料ベータの検証結果と運用原価を確認し、正式公開の承認を得ています.
