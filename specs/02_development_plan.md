## 現状

公開版は0.5.1 (2026-09-30公開) です. 公開Versionの正本は`Drafta_Web/package.json`です.

- 利用にはGoogleログインが必須です. 未ログインでは編集画面を表示せず, 未ログインの編集可能なPreviewは0.5.0で撤廃しました. Landing-pageはログインなしで閲覧できます.
- Memo･Tray･設定はFirestoreへ保存し, 同一アカウントの端末間で同期します. 同じMemoの競合では原文と競合コピーを保持し, Tray･順序･削除等の構造競合は確認付きで保管します.
- Googleログイン後のMemoに保存履歴があり, 選択した版を別Memoへ復元できます.
- 認証喪失時の未保存編集はページ内で元アカウント専用に保留し, 同じアカウントで再ログインした後にサーバー版と照合して復旧します.
- 未対応: 再読み込み･ブラウザー終了後の未保存編集の復元, オフライン編集の永続保管, 手動バックアップ･復元UI, プロファイル, フィードバックフォームです.
- 本番の個人データを使った保存履歴の記録･復元と, 実際の認証失効からの復旧は未検証です. 競合･復旧の操作検証はローカル模擬DBで行いました.

## 今後の方針

基本順序は「Googleログイン･永続保存 → 同期･障害復旧 → 広告なしの無料β検証 → 有料化」とします. 2026-09-28の指示により, 手動バックアップ･復元UIは後続へ移し, 永続保存の前提条件にはしません. サービス側のデータ保護･復旧設計は保存基盤と並行して扱います.
無料βは全機能の完成まで待たず, 保存･同期の安全性を確認して開始します. 移行･連携･共有はβ中に段階的に追加できます.

| 段階 | 採用する内容 | 現在の状態･開始条件 |
|---|---|---|
| 1. 保存の土台 | Googleログイン･永続保存を優先し, 同期･障害復旧を続けて実装します. | ログイン･永続保存 (0.2.0), 同期･競合復旧 (0.3.0), 保存履歴 (0.4.0), ログイン必須化と認証喪失時の復旧 (0.5.0〜0.5.1) を公開済みです. 残りは本番での実利用確認と, 障害時に利用者が取る手順の整備です. |
| 2. 無料βの準備 | プロファイルの作成･削除, バージョン番号, アップデート報告, フィードバックフォームを用意します. | バージョン番号と更新履歴は本番反映済みです. プロファイルとフィードバックフォームは未着手です. プロファイルによるデータ分離を考慮します. |
| 3. 移行･連携 | Notion / Obsidian / Evernoteからのインポートと, Codex向けMCP連携を進めます. | Obsidianの取り込み仕様を確定しました (未実装). 順序はObsidian → Notion → Evernoteとします. MCPは未着手です. |
| 4. Memo共有 | Memoの共有機能を実装します. | 未着手です. 公開範囲･閲覧/編集権限･共有解除を設計します. |
| 5. 正式サービス | 無料βの実用性･運用費を確認して有料化します. | 未着手です. 料金･容量･契約条件･課金開始日･正式公開は未確定で, 別途承認します. |
| 6. モバイル展開 | iOS / Androidのネイティブアプリを開発します. | 未着手です. Webの保存･同期基盤を確立後, 技術方式とストア対応を検討します. |

インポート･MCP･共有のすべてを有料化の必須条件にはしません. 無料βの結果から, 正式提供に必要な範囲を別途判断します.
Appleログインは後続段階です. 初期βに広告は付けず, 正式提供後の広告方針は未確定とします.

## 次の作業

1. 保存履歴と認証喪失時の復旧を本番で実利用確認します. 本番ユーザーのデータは使わず, テスト用Memoで行います. 認証失効や削除など失敗を誘発する操作を本番アカウントへ行う前に, 内容と影響を示してGlesさんへ確認します.
2. 保存失敗･認証喪失･競合･誤削除の際に利用者が取る手順を整えます. 公開範囲 (アプリ内案内, Landing-page等) は作成前に決めます.
3. 無料βの準備として, プロファイルの作成･削除とフィードバックフォームの設計前確認事項 (下記) を整理します.
4. Obsidianからの取り込みは2026-10-08に仕様を確定しました ([14_import.md](14_import.md)). 実装と公開は1の実利用確認で問題がないと確認してから行います. Notion･Evernoteは後続です.

変更箇所と影響範囲に応じて検証し, 小変更のたびに全テストを実行しません.
通常のアプリ更新は, 2026-09-30に承認された継続的な実行許可により検証・Commit・Push・HostingへのDeploy・公開確認まで進めます. 内部文書のみの変更ではDeployしません. 課金・認証方式・アクセス権限・本番データの削除や移行は別途明示承認を得ます.

## 設計前に確認する事項

- プロファイル: 同じアカウント内の独立したMemo･Tray構成を指すかは未確定です. 仕事用･個人用などの区分は例であり, 確定仕様ではありません.
- 新規プロファイル: 空の状態とサンプル付きの選択, 初期選択, 設定の共有範囲を決めます. 「まっさらで開始したい」という既存希望を考慮します.
- プロファイル削除: 復元猶予･関連Memoと保存履歴の扱い･最後のプロファイル削除･同期中の削除を定義します.
- バックアップ: 手動UIは後続です. 再開時は現在のワークスペース全体の置き換え, 復元前バックアップと取り消し付きという採用案を基に, 永続保存･保存履歴と整合させます. 複数プロファイルへの対応は別途設計します.
- インポート: 各サービスの対応エクスポート形式, 画像･リンク･階層･書式の変換範囲, 欠落の通知, 容量制限を定義します. 任意HTML/JSONを既存変換器へ直接渡しません.
- MCP: 読み取り/書き込み範囲, プロファイル選択, 認証, 削除等の確認, 監査と接続解除を設計します. Codexから操作可能にするための連携として扱います.
- Memo共有: リンク公開と招待制のどちらを提供するか, 所有者･権限･解除後の挙動を決めます.
- フィードバック: 送信先･収集情報･個人情報の扱いを決めます. バージョン番号方式と更新履歴の表示場所は[バージョン運用](09_release_versioning.md)で確定済みです.
- ネイティブアプリ: Expo + TenTapは過去の候補です. 採用方式･オフライン範囲･通知･ストア課金との整合は未確定です.
