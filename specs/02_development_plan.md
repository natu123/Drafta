## 今後の方針

基本順序は「バックアップ･復元 → Googleログイン･永続保存 → 同期･障害復旧 → 広告なしの無料β検証 → 有料化」とします.
無料βは全機能の完成まで待たず, 保存･同期の安全性を確認して開始します. 移行･連携･共有はβ中に段階的に追加できます.

| 段階 | 採用する内容 | 現在の状態･開始条件 |
|---|---|---|
| 1. 保存の土台 | バックアップ･復元, Googleログイン･永続保存, 同期･障害復旧を実装します. | バックアップ基盤まで実装済みです. プロファイルによるデータ分離を保存設計時から考慮します. |
| 2. 無料βの準備 | プロファイルの作成･削除, バージョン番号, アップデート報告, フィードバックフォームを用意します. | バージョン番号と更新履歴は本番反映済みです. プロファイルとフィードバックフォームは未着手です. |
| 3. 移行･連携 | Notion / Obsidian / Evernoteからのインポートと, Codex向けMCP連携を進めます. | 未着手です. 対応順序･形式･権限範囲は実装前に決めます. |
| 4. Memo共有 | Memoの共有機能を実装します. | 未着手です. 公開範囲･閲覧/編集権限･共有解除を設計します. |
| 5. 正式サービス | 無料βの実用性･運用費を確認して有料化します. | 未着手です. 料金･容量･契約条件･正式公開は別途承認します. |
| 6. モバイル展開 | iOS / Androidのネイティブアプリを開発します. | 未着手です. Webの保存･同期基盤を確立後, 技術方式とストア対応を検討します. |

インポート･MCP･共有のすべてを有料化の必須条件にはしません. 無料βの結果から, 正式提供に必要な範囲を別途判断します.
Appleログインは後続段階です. 初期βに広告は付けず, 正式提供後の広告方針は未確定とします.

## 次の作業

1. プロファイルの意味と, バックアップが扱う範囲を確定します.
2. バックアップのダウンロード･ファイル選択･検証結果表示･復元確認UIを実装します.
3. JSONからアプリ状態へ適用し, 既存データを無断で失わない復元を確認します.

変更箇所と影響範囲に応じて検証し, 小変更のたびに全テストを実行しません.
本番環境･料金･権限を変更する操作は, 従来どおり明示承認を得ます.

## 設計前に確認する事項

- プロファイル: 同じアカウント内の独立したMemo･Tray構成を指すかは未確定です. 仕事用･個人用などの区分は例であり, 確定仕様ではありません.
- 新規プロファイル: 空の状態とサンプル付きの選択, 初期選択, 設定の共有範囲を決めます. 「まっさらで開始したい」という既存希望を考慮します.
- プロファイル削除: 復元猶予･関連Memoの扱い･最後のプロファイル削除･同期中の削除を定義します.
- バックアップ: 現行のワークスペース形式と, 単一/全プロファイルの書き出し･復元先･ID衝突･互換性を整理します.
- インポート: 各サービスの対応エクスポート形式, 画像･リンク･階層･書式の変換範囲, 欠落の通知, 容量制限を定義します. 任意HTML/JSONを既存変換器へ直接渡しません.
- MCP: 読み取り/書き込み範囲, プロファイル選択, 認証, 削除等の確認, 監査と接続解除を設計します. Codexから操作可能にするための連携として扱います.
- Memo共有: リンク公開と招待制のどちらを提供するか, 所有者･権限･解除後の挙動を決めます.
- バージョン･報告: 番号方式, アップデート履歴の表示場所, フィードバック送信先･収集情報･個人情報の扱いを決めます.
- ネイティブアプリ: Expo + TenTapは過去の候補です. 採用方式･オフライン範囲･通知･ストア課金との整合は未確定です.

## 後続の検討候補

- Windows / macOS / Linuxのデスクトップ版とTauriは既存の構想として保持します. 今回の6段階の必須条件にはしません.
- オフライン対応は別途検討します. 現在のクラウド保存方針を無断でオフライン優先へ変更しません.
- 旧仕様のFree 200MB / Pro 10GB･月額3 USD / 追加10GB･月額2 USDは過去の設計値です. 確定した公開料金ではありません.
- Landing-pageは現在利用できる機能と将来予定を区別します. 詳細なロードマップや日付を公開する場合は, 対応範囲と表現を先に確定します.
