# 公開バージョンと更新履歴

採用日: 2026-09-28.

- 公開バージョンの起点を Version 0.1.0 とします. 採用時点 (0.1.0) はWeb試験公開で, 永続保存は未対応でした. 永続保存は0.2.0で公開しました.
- 番号の正本は `Drafta_Web/package.json` の `version` とします. 既に0.1.0のため今回の番号変更はありません. 今後の更新ではLock-fileも整合させます.
- 小さな修正はPATCH (例: 0.1.1), まとまった機能追加はMINOR (例: 0.2.0)を上げます. 0.9.0の次は0.10.0であり, 小数として扱いません.
- 正式提供の準備が整った段階で1.0.0を判断します. 有料化と同時である必要はありません. 0系のデータ形式変更は互換性と移行方法を別途明示します.
- 現在番号は `src/lib/release-info.ts` から表示します. 公開履歴の番号･日付は固定値のRELEASESに残し, 次回は新しい項目を先頭へ追加します. 過去の項目を新しい番号で上書きしません.
- `release-copy.ts` の11言語へ履歴本文を追加し, RELEASESのcopyKeyで参照します. 履歴ページは `/updates/`, Landing-pageには最新項目とリンクだけを掲載します.
- 日付は初回0.1.0の運用開始日です. 公開が別日になった場合はDeploy前に実際の日付へ揃えます. 今回の実装完了だけでは本番反映済みとは扱いません.
- 運用開始前の履歴はGitで確認できる実装日別の主要項目として扱います. 過去の版番号や, 確認できない公開日を作りません.
- 過去分の根拠: 2026-09-28 `a6867c8` (編集ツールバー), 2026-09-17 `e13f9fb`等 (Tray･Memoピンとノート内検索), 2026-09-16の一覧内作成･改名とコードフェンス修正の各コミットです.

## アップデートごとの必須更新

- 利用者に影響する機能追加･修正･表示変更は, バージョン番号･更新履歴･Landing-pageの最新情報をセットで更新します. 内部文書や開発環境のみの変更では, 公開番号や利用者向け履歴を機械的に増やしません.
- Commitごとではなく公開リリース単位で番号を決めます. 公開前の追加修正は同じリリースへまとめ, 公開済みの履歴は維持します.
- package.jsonとLock-fileの番号を揃え, RELEASESへ実際の公開日と新しい項目を追加します. 履歴本文は11言語へ反映し, 利用者にとって何が変わるかを簡潔に記載します.
- Landing-pageの番号と最新履歴は共通データから更新します. あわせてロードマップ･機能説明･保存等の注意書きを確認し, 実装済みの項目を予定のまま残さず, 未実装の項目を完了扱いしません.
- 保存等の注意書きはLanding-pageの注意枠の1か所だけに置き, 更新履歴の各版には繰り返し表示しません (2026-10-21, Glesさんの指摘で各版の注意書きと過去版用の注意書きの文言を削除).
