# 公開バージョンと更新履歴

採用日: 2026-09-28.

- 公開バージョンの起点を Version 0.1.0 とします. 現在はWeb試験公開であり, 永続保存は未対応です.
- 番号の正本は `Drafta_Web/package.json` の `version` とします. 既に0.1.0のため今回の番号変更はありません. 今後の更新ではLock-fileも整合させます.

- 運用開始前の履歴はGitで確認できる実装日別の主要項目として扱います. 過去の版番号や, 確認できない公開日を作りません.

## 公開時の確認

### Version 0.2.0 (公開準備済み･未Deploy)

GoogleログインとMemo･Tray･設定の自動保存をまとまった機能追加として0.2.0にします. PackageとLock-file, 11言語の更新履歴, Landing-pageの保存条件･今後の計画を揃えました. 過去の履歴には当時の保存未対応の説明を保持します. 本番接続設定をプロセス環境へ渡したBuildが成功し, 静的生成物でも本番DBから復元できることをChromeで確認しました. 公開日2026-09-28はDeployが別日になる場合に更新します.

今後の公開Buildでも`NEXT_PUBLIC_FIREBASE_MODE=production`と登録済みアプリの接続設定が必要です. 未指定Buildはプレビュー動作となるため公開しません. APIキーをGitやログへ記載せず, 生成物中のプロジェクト･アプリ識別と実画面のログイン導線を確認します.

番号と履歴の一致, 対応言語, 保存未対応等の注意, 履歴へのリンク, canonicalとsitemapを確認します. 実装確認と本番公開確認を区別し, Deployは明示承認後に行います.

## アップデートごとの必須更新

- 利用者に影響する機能追加･修正･表示変更は, バージョン番号･更新履歴･Landing-pageの最新情報をセットで更新します. 内部文書や開発環境のみの変更では, 公開番号や利用者向け履歴を機械的に増やしません.
- Commitごとではなく公開リリース単位で番号を決めます. 公開前の追加修正は同じリリースへまとめ, 公開済みの履歴は維持します.
- package.jsonとLock-fileの番号を揃え, RELEASESへ実際の公開日と新しい項目を追加します. 履歴本文は11言語へ反映し, 利用者にとって何が変わるかを簡潔に記載します.
- Landing-pageの番号と最新履歴は共通データから更新します. あわせてロードマップ･機能説明･保存等の注意書きを確認し, 実装済みの項目を予定のまま残さず, 未実装の項目を完了扱いしません.
- 公開前に番号･掲載内容･リンクの整合性を対象範囲で確認します. 履歴更新だけを理由に全テストを繰り返しません.
- 本番Deployの承認後, 公開版の番号と最新履歴を確認し, 開発計画の現状･今後の方針･次の作業も更新します. この更新義務は自動Deployの許可ではありません.
