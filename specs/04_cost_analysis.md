## ユーザー使用量の想定

### ストレージ使用量分布
| ユーザー層 | 割合 | 200MB上限時 |
|-----------|------|-------------|
| ライト（たまに使う） | 80% | 20MB |
| 普通 | 15% | 50MB |
| ヘビー（上限まで使う） | 5% | 200MB |
| **加重平均** | | **約34MB** |

### 理由
- ほとんどのユーザーは上限に達しない
- 上限を変えても平均使用量はほぼ同じ
- ヘビーユーザー（5%）のみが上限に到達

## 1万人Freeユーザーの採算シミュレーション

### 前提条件
- Proユーザー: 0人
- Freeユーザー: 10,000人
- Free上限: 200MB
- 平均使用量: 34MB/人
- ダウンロード: ストレージの50%（ブラウザキャッシュ考慮）
- 広告eCPM: $1（1000表示で$1）
- 月間広告表示: 30回/人（1日1回利用）

### ストレージコスト
| 項目 | 計算 | 月額 |
|------|------|------|
| 合計ストレージ | 34MB × 10,000人 = 340GB | - |
| ストレージ費用 | 340GB × $0.026 | $8.84 |
| ダウンロード費用 | 170GB × $0.12 | $20.40 |
| **小計** | | **$29.24** |

### Firestoreコスト
| 操作 | 月/人 | 合計回数 | コスト |
|------|-------|---------|--------|
| 書き込み | 500回 | 500万回 | $9.00 |
| 読み取り | 1,000回 | 1,000万回 | $6.00 |
| **小計** | | | **$15.00** |

### 広告収益
```
10,000人 × 30表示/月 = 300,000インプレッション
300,000 ÷ 1,000 × $1 = $300/月
```

### 損益計算
| 項目 | 金額 |
|------|------|
| コスト合計 | $44.24 |
| 広告収益 | $300.00 |
| **月間利益** | **+$255.76** |

## ストレージ上限別の比較

### 1万人Freeユーザーの場合

| 上限 | 平均使用量 | 月間コスト | 広告収益 | 月間利益 |
|------|-----------|-----------|---------|---------|
| 200MB | 34MB | $44.24 | $300 | **+$255.76** |
| 500MB | 80MB | $83.80 | $300 | **+$216.20** |
| 1GB | 130MB | $126.80 | $300 | **+$173.20** |

### 結論
- どの上限でも黒字
- 200MBと500MBの差は月$39.56程度
- UXとPro誘導のバランスで200MBを選択

## Proユーザーの採算

### 1人あたりのコスト（10GB上限、平均3GB使用）
| 項目 | 計算 | 月額 |
|------|------|------|
| ストレージ | 3GB × $0.026 | $0.08 |
| ダウンロード | 1.5GB × $0.12 | $0.18 |
| Firestore | ヘビー想定 | $0.10 |
| **合計コスト** | | **$0.36** |
| **収入** | | **$3.00** |
| **利益** | | **$2.64** |

### 追加ストレージ（+10GB/$2）
| 項目 | 計算 | 月額 |
|------|------|------|
| ストレージ | 10GB × $0.026 | $0.26 |
| ダウンロード | 5GB × $0.12 | $0.60 |
| **合計コスト** | | **$0.86** |
| **収入** | | **$2.00** |
| **利益** | | **$1.14** |

### 追加ストレージ価格の検討過程（$1 vs $1.5 vs $2）

前提: +10GBあたりの原価は `$0.86/月`（Storage `$0.26` + Download `$0.60`）

| 価格 | 粗利/月 | 評価 |
|------|---------|------|
| $1.00 | $0.14 | 薄利。決済手数料・為替変動で赤字化しやすい |
| $1.50 | $0.64 | 実用域だが、想定外トラフィック時の余裕は限定的 |
| **$2.00** | **$1.14** | 安全マージンが取りやすく、運用が安定 |

#### 決定
- **採用価格: +10GB = $2/月**
- 理由:
  - インフラ原価に対して十分な利益幅を確保できる
  - 決済手数料・為替・ダウンロード増加リスクを吸収しやすい
  - 初期運用フェーズで価格を下げるより、先に安定性を優先する

## 月間ストレージ vs 総ストレージの検討

### 月間ストレージ（Evernote方式）
```
月200MBアップロード可能
→ 1年で2.4GB蓄積
→ 2年で4.8GB蓄積
→ コストが膨らみ続ける
```

### 総ストレージ（Drafta採用）
```
200MB上限 = それ以上保存できない
→ コスト上限が予測可能
→ 個人開発に適している
```

### 決定: 総ストレージ方式を採用
- シンプルで実装しやすい
- Freeユーザーのコスト上限が予測可能
- 個人開発には安全な選択

## デバウンス設定

### 採用: 条件付きハイブリッド

### 競合比較
| サービス | デバウンス |
|---------|-----------|
| Notion | 約1秒（アクティブ時） |
| Evernote | 約0.3秒 |
| **Drafta** | **入力中0.8秒 + 重要イベント即時保存** |

### コスト影響（1日1時間編集のヘビーユーザー）
| 方式 | 書き込み/月（目安） | コスト/月（目安） |
|------|------------------|------------------|
| 0.5秒固定 | 216,000回 | $0.39 |
| 1秒固定 | 108,000回 | $0.19 |
| **ハイブリッド（0.8秒 + 即時保存）** | **120,000〜160,000回** | **$0.22〜$0.29** |

### 結論
- 0.5秒固定より書き込みコストを抑えつつ、体感速度を維持しやすい
- 重要イベントで即時保存するため、保存漏れリスクを抑制できる
- 現時点の採算性とUXのバランスが最も良い

## まとめ

### 収益構造
1. **Freeユーザー**: 広告収益でコストをカバー、黒字運営可能
2. **Proユーザー**: $3/月で$2.64の利益、高収益
3. **追加ストレージ**: $2/月で$1.14の利益、十分な安全マージン

### リスク要因
- 広告eCPMの変動（$0.5〜$3の幅あり）
- ヘビーユーザー比率が想定より高い場合
- Firestore無料枠超過時の課金開始

### 安全マージン
- 広告eCPMが$0.5に下がっても、1万人で月$109の黒字
- Proユーザーが10%いれば、さらに安定

## リージョン方針と再評価条件

### 採用方針
- 初期運用は **Firestore `us-central1`（単一リージョン）**
- 目的: コスト最適化と運用の単純化

### 再評価する監視指標
- 月間アクティブ有料ユーザー数（Pro + 追加ストレージ）
- 保存失敗率（`保存失敗` / 全保存試行）
- 同期遅延 P95
- Firestore/Storageの月額コスト推移
- リージョン障害時の影響時間

### マルチリージョン移行を検討する目安
- 障害影響時間が許容SLOを継続的に超過
- 同期遅延P95が継続悪化し、UX影響が顕在化
- 事業フェーズ上、可用性優先の投資判断に切り替える場合
