# Notion･Evernoteからの取り込みと, 3形式への書き出し

採用日: 2026-10-23. `specs/14_import.md` (Obsidianからの取り込み) の続きです.
取り込みの流れ (端末内で読む → プレビュー → 確定後に分けて保存 → 結果画面), 上限, 文書の検証は14をそのまま使います.
UIの配置 (D6･D7) は案を示し, 同日にGlesさんの承認で案Aに確定しました.

## 目的と範囲

- NotionとEvernoteの書き出しファイルを, DraftaのTray･Memoとして取り込みます. 取り込みは新しいTrayへの追加だけです (14と同じ).
- ワークスペースを, Obsidian (Vaultのzip), Notion (取り込めるMarkdownのzip), Evernote (`.enex`) の3形式で書き出します. 書き出しは端末内で作り, サーバーへは送りません.
- 画像･添付ファイル･Memo間リンクは, 14と同じく取り込みません. 取り込めなかった要素は, 本文に名前を残すか結果画面で知らせます.

## 調べた形式 (2026-10-23)

### Notionの書き出し

- 形式は「Markdown & CSV」「HTML」「PDF」です. 書き出しはzipで, 下位ページはページ名のフォルダに入ります ([Notion: Export your content](https://www.notion.com/help/export-your-content)).
- ファイル名とフォルダ名の末尾に, 半角空白と32桁のID (16進) が付きます (例: `会議メモ 1a2b….md`, `会議メモ 1a2b…/`). 取り込み時にIDを外します.
- 大きなワークスペースでは, zipの中に`Export-…-Part-1.zip`のような分割zipが入ります ([Obsidian Help: Import from Notion](https://obsidian.md/help/import/notion)). 外側のzipの直下にあるzipは1段だけ開きます. 分割zipを直接 (複数) 選ぶこともできます.
- データベースはCSV (`名前 ID.csv`, 新しい書き出しでは全行の`名前 ID_all.csv`も) と, 行ごとのページ (`名前 ID/行.md`) になります. Markdownの行ページは, 先頭の`# タイトル`の後にプロパティを`名前: 値`の行で持ちます.
- MarkdownではCalloutが`<aside>`のHTMLになります. HTMLの書き出しは, 1ページ1ファイルで, `h1.page-title`, `table.properties`, `div.page-body`を持ちます. To-doは`ul.to-do-list`と`div.checkbox-on/off`, Toggleは`details`, Calloutは`figure.callout`, 数式は`figure.equation`のTeX注記 (`annotation`) です.

### Evernoteの書き出し (ENEX)

- `.enex`はXMLです. ルート`en-export`の下に`note`が並び, 各noteは`title, content, created?, updated?, tag*, note-attributes?, task*, resource*`の順です ([evernote-export4.dtd](http://xml.evernote.com/pub/evernote-export4.dtd)). 日時は`20261023T123456Z` (UTC) です.
- 本文 (`content`) はCDATAの中のENML (XHTMLの部分集合, ルート`en-note`) です. 独自要素は`en-media` (添付. hashとtypeが必須), `en-todo` (checked), `en-crypt` (暗号化テキスト) です. id･class･イベント属性は使えません ([enml2.dtd](http://xml.evernote.com/pub/enml2.dtd)).
- Evernote 10の書き出しは, チェックリストを`li style="--en-checked:true;"`, コードブロックを`div style="--en-codeblock:true;"`で表します. タスク (`task`) はnoteの外の要素で, 本文には`--en-task-group:true; --en-id:…`の空の`div`だけが残ります.
- ノートブック名はENEXに入りません. ノートブックごとに`.enex`ファイルを分けて書き出すため, ファイル名をTray名にします.
- 添付は`resource`にBase64で入ります. 数百MBになることがあります.

### Notionの取り込み (書き出し先として)

- Notionは`.md`･`.html`･`.zip`などを取り込めます. フォルダをzipにすると構成を保ちます. zipは5GBまでで, 1万ファイルを超えると失敗しやすいとされています ([Notion: Import data into Notion](https://notion.com/help/import-data-into-notion)).
- Markdownは見出し･リスト･コードブロックを取り込めます. 独自拡張は崩れることがあります.
- ページ名をファイル名と先頭の`# 見出し`のどちらから取るかは, 公式の説明が見つかりませんでした. APIでは先頭のH1を題名にします. Notion自身の書き出しと同じく, 先頭に`# 題名`を置きます (要確認: 実際のNotionで題名が二重にならないか).

### D2. NotionのページとTrayの対応

DraftaのTrayは1階層です. Obsidianの「最上位フォルダ = Tray」(14のD2) にそろえます.

| 案 | 内容 |
|---|---|
| A (採用) | 下位ページを持つ最上位ページごとに, Tray「Notion / ページ名」を作り, そのページ自身と下位のすべてのページを入れます. 下位ページのない最上位ページは, Tray「Notion」へまとめます. 対応するページのない最上位フォルダ (チームスペース等) は, Tray「Notion / フォルダ名」にします. |
| B | すべてを1つのTray「Notion」へ入れます. 階層は失われます. |
| C | 階層ごとにTray「Notion / 親 / 子」を作ります. Trayが多くなります. |

- Memoの題名は, Markdownは先頭の`# 題名`, HTMLは`h1.page-title`, なければIDを外したファイル名です.
- Tray内の並びは14と同じ (日時でリストスタイルの側へ, 同じ日時ならページの木の順: 親の次に子, 名前の自然順) です. Notionの書き出しには作成･更新日時がないため, zip内の日時 (書き出した時刻) を使います.
- Notionのページアイコンが絵文字1つなら, Memoのアイコンにします. それ以外は📝です.

### D3. Notionで取り込めない要素

| 要素 | 扱い |
|---|---|
| 画像･ファイル･動画･埋め込み | 取り込まず, 本文に`[画像: 名前]` / `[添付: 名前]`を残し, 件数を知らせます (14と同じ). zip内の画像ファイルなどは「取り込めないファイル」に並べます. |
| ページ間リンク | 表示名の文字として残します. |
| データベース | 行ごとのページはMemoとして取り込みます (プロパティは本文先頭の`名前: 値`の行). CSVは1つのMemo (表) にします. `_all.csv`があるときはそちらだけを使います. |
| 大きな表 | 1 Memoの表の上限 (行数×セル数の合計が10万まで, `workspace-backup.ts`) を超える表は, 行ごとの段落 (セルを` | `でつなぐ) にします. 表のためにページ全体を落とさないためです. |
| プロパティ (HTML) | 本文の先頭に`名前: 値`の段落として残します. |
| Callout | 引用にします. 絵文字のアイコンは先頭の文字として残します. |
| Toggle | 見出しの段落と中身の段落にします (開閉は失われます). |
| 数式 | TeXをコードブロック (`latex`) にします. 文中の数式はインラインコードです. |
| 色･ハイライト･文字の大きさ | 外します (他アプリの色はダークモードで読めなくなることがあるため). |
| 目次･段組み･ブックマーク | 目次は外し, 段組みは上から順に並べ, ブックマークは題名のリンクにします. |
| コメント | 取り込みません. |
| 入れ子のリスト | Markdownは14と同じく1段にします. HTMLは6段まで保ち, それより深いリストは6段目の項目の中の段落にします. |
| 空行 | Notionはすべてのブロックの間に空行を入れるため, Markdownの空行は空の段落にしません (表と表の間だけ, 区切りに1つ残します). コードブロックの中の空行は残します. |

### D4. Evernoteのノートブック･タグ･日時･タスク

| 項目 | 採用する扱い |
|---|---|
| ノートブック | `.enex`ファイルごとに, ファイル名のTrayを作ります. 複数のファイル (と, それらを入れたzip) を一度に選べます. |
| 日時 | `created`と`updated`をMemoの作成･更新日時にします. ない場合はファイルの日時です. |
| タグ | 本文末尾へ`#タグ`の文字として残します (14のFrontmatterのtagsと同じ). 空白は`_`にします. |
| タスク (Evernote 10) | 本文のタスクの位置 (`--en-task-group`) にチェックリストとして入れます. 完了は`completed`で判断します. 位置の分からないタスクは末尾に並べます. 期限･リマインダー･フラグは取り込みません. |
| 添付･画像 (`en-media`) | 取り込まず, 本文に`[画像]` / `[添付]`を残し, 件数を知らせます. `resource`のデータは読み飛ばします. |
| 暗号化テキスト (`en-crypt`) | 取り込まず, 本文に`[暗号化テキスト]`を残し, 件数に含めます. |
| `note-attributes` (作成者･出典URL･位置等) | 取り込みません. |
| チェックリスト | `en-todo` (行の先頭) と`--en-checked` (Evernote 10) をチェックリストにします. 行の途中の`en-todo`は☐･☑の文字にします. |
| コードブロック | `<pre>`と`--en-codeblock`をコードブロックにします. |
| 色･フォント･ハイライト | 外します. 太字･斜体･下線･取り消し線は`font-weight`等のstyleからも読み取ります. |

### D5. 書き出しの形式

| 書き出し | 形 | 内容 |
|---|---|---|
| Obsidian | `Drafta-obsidian-日付.zip` | `Drafta/Tray名/題名.md`. 展開したフォルダをそのままVaultとして開けます. 題名はファイル名だけで表し, 本文に`# 題名`を置きません. |
| Notion | `Drafta-notion-日付.zip` | `Drafta/Tray名/題名.md`. Notionの「インポート」でzipのまま選べます (フォルダがページになります). 各ファイルの先頭に`# 題名`を置きます. |
| Evernote | `Drafta-evernote-日付.zip` | Trayごとの`Tray名.enex`. Evernoteで各ファイルを読み込むと, ファイル名のノートブックになります. |

- 対象は削除済みでないTrayの, 削除済みでないMemoです (区切り線･復元一覧は除きます). 初期サンプルは表示中の言語の内容で書き出します.
- zip内の日時は, Memoの更新日時です (展開するとファイルの更新日時になり, Obsidianでの並びやDraftaへの再取り込みで使えます).
- ファイル名: `\ / : * ? " < > | # ^ [ ]`と制御文字を`_`にし, 前後の空白と末尾の`.`を外し, 100文字までにします. Windowsの予約名 (CON等) には`_`を付けます. 空なら表示言語の「無題のメモ」です. 同じフォルダで重なる名前には` 2`, ` 3`を付けます (大文字･小文字を区別しない).
- Markdown (Obsidian･Notion) で失われるもの: 文字色, 下線, 連続する空行, 表のセル結合 (空のセルで埋めます) と列幅, 表のセル内の改行以外の構造 (`<br>`でつなぎます), Memoのアイコン･ピン･並び順, 作成日時 (更新日時はファイルの日時に残ります).
- ENEXで失われるもの: Memoのアイコン･ピン･並び順. 色は`span style="color"`で残し, チェックリストは`en-todo`, コードブロックは`pre`にします.
- Markdownの本文は, `\ ` * _ [ ] < > | ~ $ #`と, 行頭のリスト記号に見える文字をエスケープします. Drafta-MDの色タグも, 文字ではなく書式なので書き出しません (色は外れます).

## 安全性

- 取り込むファイルはすべて信頼しません. 変換結果は, 14と同じく`editorHtmlToDocument`と保存時の検証 (`parseWorkspaceBackup`) を通し, 通らないファイル･ノートは「変換できません」として除きます.
- HTML (NotionのHTML, EvernoteのENML) は`template`要素で読み込みます (scriptは動かず, 画像も読み込まれません). その後, 許可した要素だけを書き直す変換 (`imported-html.ts`) で, 段落･見出し1〜3･リスト･チェックリスト･引用･コード･区切り線･表と, 太字･斜体･取り消し線･下線･インラインコード･リンクだけを作ります. 属性は残しません. リンクはhttp･https･mailtoだけです (14の`safeLinkUrl`). style･class･id･イベント属性･script･iframe･form等は出力に届きません. 50段より深い入れ子は文字だけにします.
- 読み込んだノードは`template`の文書 (閲覧文脈のない文書) の外へ移しません. ページの`document`で作った要素へ移すと, その時点で`img`の読み込みと`onerror`が動きます. 実装中にChromeで, プレビューの段階で`onerror`が動くことを確かめて修正し, ページの`document`には`template`以外の要素を作らないことを単体テストで確かめています (jsdomは画像を読み込まないため, 動作そのものは単体テストでは再現しません).
- ENEXのXMLは, ファイルを`<note>`ごとに区切って読みます. ファイルのDOCTYPE (内部実体の宣言を含む) は読まないため, 実体の展開 (billion laughs) や外部実体は起きません. `resource`のデータは保持せずに読み飛ばします. 1ノートは添付を除いて8MBまでです.
- zipは, 中央ディレクトリを読み, 必要なファイルだけを展開します (ブラウザー標準の`DecompressionStream`). 上限:
  - 項目は5万まで. 中央ディレクトリは16MBまで. 暗号化と, 格納･Deflate以外の圧縮方式は「非対応の形式」です.
  - 取り込むファイル (`.md`･`.html`･`.csv`) は, 宣言された大きさと実際に展開した大きさの両方を14の2MBで止めます (zip bomb対策). CRC-32が合わないものは「変換できません」です.
  - 1回の取り込みで展開して読む文字の合計は256MBまでです. 入れ子のzipは外側の直下の1段だけで, 格納 (無圧縮) ならそのまま, 圧縮されていれば256MBまで展開して読みます.
  - `.enex`はzipの中でも展開しながら読み, 2GBまでです.
  - パスの`..`･絶対パス･隠しフォルダ (`.`始まり)･`__MACOSX`は使いません. ファイルは書き出さないため, パスは表示とTrayの対応にだけ使います.
- 件数･容量の上限 (1万Memo･1000 Tray･64MB) は14と同じく保存前に確認します.

## 実装

- 共通: `obsidian-import.ts`の`buildImportedNote` (1 Memoの検証と大きさ), `orderPlan` (Tray内の並び). プレビュー･分割保存･結果画面は`import-dialog.tsx`をそのまま使います.
- zip: `zip.ts` (読み: 中央ディレクトリ, 展開の上限, CRC-32. 書き: `CompressionStream`, UTF-8名, 拡張日時).
- HTMLの変換: `imported-html.ts`. Notion: `notion-import.ts`. Evernote: `evernote-import.ts`. 書き出し: `workspace-export.ts`. 画面: `import-dialog.tsx`, `export-dialog.tsx`, 設定Dialogの「データ」区分. 文言: `transfer-copy.ts` (11言語).
- ObsidianのVaultもzipで選べるようにします (14のD1の案B. スマホでフォルダを選べない場合のため). Vaultのフォルダをzipにしたものはフォルダ名を, ファイルを直接zipにしたものはzipの名前をVault名にします.
- Obsidianの変換器 (Notionのmarkdownも使う) に, CommonMarkのバックスラッシュエスケープ (`\*`は文字の`*`) と, 長いバッククォートで囲むインラインコード (``` ``a`b`` ```) を加えました. Draftaが書き出したMarkdownを読み戻すと元の文字に戻ります. 以前は`\`が文字として残っていました.
- 設定Dialogは, 「データ」区分の分だけ背が高くなり, 高さ650pxの画面で上下がはみ出して書き出しButtonに届かなかったため, 画面の高さまでにしてスクロールさせます (`settings-dialog.tsx`).

取り込み (Draftaの設定 → データ → インポート):

1. Notionの「Markdown & CSV」: Notionの設定の「エクスポート」(またはページの「…」→「エクスポート」) で, 形式「Markdown & CSV」, 含めるコンテンツ「すべて」, 「サブページを含める」と「サブページ用のフォルダを作成」をオンにします. ダウンロードしたzipを展開せずに, 取り込み元「Notion」で選びます. 見る点: Tray名 (「Notion / ページ名」), Memoの題名にIDが残らない, To-do･Callout (引用)･表･コード, データベースのCSVが表のMemoになる, 画像の件数の表示と「取り込めないファイル」の一覧.
2. Notionの「HTML」: 同じ設定で形式だけ「HTML」にします. 見る点: 絵文字のページアイコンがMemoのアイコンになる, プロパティが本文の先頭に「名前: 値」で並ぶ, Toggle･Calloutの中身, コードの言語, 色や文字の大きさが残らない.
3. 大きなワークスペース: ダウンロードしたzipの中に`…-Part-1.zip`などが入っていれば, 外側のzipをそのまま選び, すべての部分が取り込まれるかを見ます.
4. Evernote: ノートブックの「…」→「ノートブックをエクスポート」(またはノートを選んで「エクスポート」) で`.enex`を作り, 複数のファイルを一度に選びます. 見る点: ファイル名のTray, Memo一覧の日付がEvernoteの作成･更新日時と合う, 末尾の`#タグ`, 古い形式と新しい形式のチェックリスト, Evernote 10のタスクが元の位置にチェックリストとして入る, コードブロック, 添付の`[画像]`･`[添付]`と件数. 大きな添付のあるノートブックで, 読み込みの時間も見ます.

書き出し (Draftaの設定 → データ → エクスポート):

5. Obsidian: zipを展開し, Obsidianの「フォルダを保管庫として開く」で`Drafta`フォルダを開きます. 見る点: Trayのフォルダ, ファイル名, チェックリスト･表･コード, `#`･`*`･`<`などを含む文に`\`が見えない, ファイルの更新日時がMemoの更新日時.
6. Notion: Notionの「インポート」でzipを展開せずに選びます. 見る点: Drafta → Tray → Memoのページの入れ子, 題名が二重にならないか (本文の先頭に同じ見出しが残らないか), To-do･表･コード. 二重になる場合は, Notion向けの先頭の`# 題名`を外します.
7. Evernote: zipを展開し, Evernoteの「ファイル」→「インポート」→ ENEXで各`Tray名.enex`を読み込みます. 見る点: ノートブック名, 作成･更新日時, チェックリスト, 文字色, コード, 表.

## 今回の範囲外

- 画像･添付ファイルの保存 (14と同じく, Firebase Storageと費用の承認が必要です).
- NotionのAPI連携, EvernoteのAPI連携 (どちらも書き出しファイル経由だけです).
- 書き出しへの削除済みMemo･保存履歴の同梱. Drafta同士の完全な復元にはバックアップ (`specs/07`) を使います.
