# 文書形式の基盤 (M1の一部)

## 対象と非対象

現行エディターの文書構造を保存処理でも再利用するための内部形式です. 既存アプリの状態管理はまだHTMLのままで、クラウド保存や外部ファイルのインポートには接続しません.

メモID・トレイID・並び順・日時・完了/削除状態・サンプル識別子などは、`07_workspace_backup.md`のワークスペース形式で保持します. この文書形式だけでは完全なバックアップになりません.

## 内部形式 v1

```json
{
  "format": "drafta-document",
  "schemaVersion": 1,
  "document": {
    "type": "doc",
    "content": [
      { "type": "title", "attrs": { "level": 1 } },
      { "type": "paragraph" }
    ]
  }
}
```

- タイトルは文書の先頭ノードで表現し、文書内で本文の見出しと区別します.
- 空のタイトルも有効です. 「無題のメモ」という表示文言をデータへ埋め込みません.
- 編集と変換で同じ拡張定義を使い、色・表・コード・チェックリスト・番号付きリストの独自属性を保持します.
- バージョン不一致と文書スキーマ不適合はエラーにします. 自動的に新形式へ上書きしません.
- HTML入力はエディターのスキーマへ正規化されます. 任意のHTMLの見た目や未知の要素を完全保存する仕様ではありません.
- CSS表記も正規化します. 例えば同じ色の16進表記とrgb表記によって、往復変換後の文書が異なるものと判定されないようにします.

## 安全条件と次段階

- 変換器はアプリが生成したデータ向けであり、外部ファイルを信頼して表示してよいという意味ではありません.
- 外部インポート前には、サイズ・深さ・型・属性・URLスキーム・ID重複・参照整合性・バージョンを別途検証します.
- バックアップUIと本番保存への接続は、上記検証と復元試験を終えてから行います.
- 新規クラウド資源、課金プラン、データベースへの書き込みは、この変更には含めません.
