# スマートフォン向けデザインとメモの操作の整理

採用日: 2026-10-23. Glesさんの依頼 (2026-10-21の「よく使う操作を人気のスマホアプリのように画面の下へ」, 2026-10-23の6項目) を, この文書の案で実装します. 版番号と更新履歴は公開の作業 (メインのSession) で付けます.

## 背景

- Draftaは PC の3カラムを前提に作られ, 操作はすべて画面の上にあります. スマホ (幅768px未満) では, 上端のヘッダー (検索・Writing Mode・アカウント・言語・設定) と, 画面ごとの見出し (戻る・トレイを開く等) が上に重なり, 親指から遠い位置に操作が集まっていました.
- エディタのタイトル行には, 左にメモのアイコン, 右に履歴と削除が絶対配置で重なり, スマホではタイトルの幅が大きく削られていました.
- スマホでは状態表示の文字が隠れ (アイコンのみ), 新しい端末で本文がそろうまでの進み具合が見えませんでした.
- Writing Mode (縦向きのタブ一覧) はスマホでは表示されず, 切り替えるとエディタだけの画面になるだけで, 戻る手段も分かりにくい状態でした.
- 他の5項目 (メモのピン操作, ピン留めの背景, チャットスタイルの追加欄, すべてのメモの追加欄) は全レイアウト共通の変更です.

## 全レイアウト共通の変更

### 1. メモの操作をタイトル行からツールバーへ

- エディタのツールバーの右端に「メモの操作」の組 (`.editor-memo-actions`) を置き, **ピン留め**・**保存履歴**・**削除**のボタンをこの順に並べます. ツールバーが折り返す幅 (スマホ等) では, 組ごと折り返した行の右端に寄ります. アラビア語 (RTL) では左端です.
- ピン留めは一覧のピンと同じ操作です (押すたびに付け外し, 付いているときはゴールド, `aria-pressed`). 削除済みのメモと区切り線には出しません. 見本メモ (編集できないWelcome等) にも出します (ピンは許可されているため).
- 保存履歴は従来どおりログインしたアプリだけ, 削除は従来どおり保護されたメモ・削除済みのメモには出しません.
- タイトル行に残すのはメモのアイコンだけです (左). タイトルの右側の余白 (44〜88px) はなくなり, タイトルは行の右端まで使えます.
- 「…」の中にまとめる案もありましたが, ピン・履歴・削除はどれも1回で届く方がよく, 従来も1回で押せたため, ボタンを並べる案にしました. 項目が増えたときは「…」への集約を検討します.

### 2. ピン留めの領域の背景

- メモ一覧のピン留めの領域 (見出し`.pinned-summary`とメモ`.pinned-items`) を1つの囲み (`.pinned-section`) にまとめ, ゴールド (#C49547) を薄く敷いた背景と枠線を付けます. ライトは10%, ダークは14%の濃さです. カードは従来どおりカードの色なので, 囲みの上に浮いて見えます.
- 折りたたんだときは見出しだけの囲みになります. カードの高さ (74px/70px, `cardHeight`と`contain-intrinsic-size`) は変えません. 囲みの余白はカードの外側にあり, 未描画のカードの空き (`.memo-list-rest`) の計算に影響しません.
- Tray一覧のピン留めは対象外です (依頼はメモ一覧).

### 3. チャットスタイルの追加欄は下に

- リストスタイルがチャットスタイル (Add to Bottom) のとき, 「トレイを追加」をTray一覧の下端, 「メモを追加」をメモ一覧の下端に置きます. 一覧のスクロールの外 (下) に固定し, 新しい項目が増える側 (下) と追加欄をそろえます. ToDoスタイルは従来どおり上端です.
- エディタの空の画面の「メモを追加」は従来どおりです.

### 4. すべてのメモにも「メモを追加」

- すべてのメモ (`:all`) にも「メモを追加」を出します. 追加先は**Tray一覧の保存順で最初の (削除されていない) Tray**です. 新しいワークスペースではInboxです. ボタンと入力欄の名前に追加先を出します (例: 「Inboxにメモを追加」).
- 理由: アプリが既定のTrayとして使うもの (前回の表示がないとき・開いていたTrayを削除したときに開くTray) と同じ規則で, 直前に何を開いていたかに左右されず, 行き先が予測できるためです. すべてのメモは「まず書き留め, 後で分ける」入口として使え, 選択・一括移動で後から分けられます. 作ったメモは更新日時が最新なので, すべてのメモでも開く側の端 (チャットスタイルは下) に出ます.
- Trayが1つもないときは出しません. 区切り線の追加とTray名の変更は従来どおり出しません.

## スマートフォン (幅768px未満) のレイアウト

### 画面の構成

上から順に, 帯 (Playgroundの案内) → 各画面の見出し → 内容 → 状態の帯 (必要なときだけ) → 下部ナビゲーションです. 上端の共通ヘッダーは出しません (タブレット・PCは従来どおり).

| 画面 (`mobilePane`) | 見出し | 内容 |
| --- | --- | --- |
| `trays` | 「トレイ」, 右にアカウント (保存状態のアイコン付き)・言語・設定・区切り線の追加 | Tray一覧 |
| `notes` | Tray名 (改名), 右に選択・区切り線の追加 | メモ一覧 |
| `editor` | エディタのツールバー (検索・Undo/Redo・書式・メモの操作) | メモ |

- 戻るボタン (エディタ→一覧, トレイ→一覧) と一覧の「トレイを開く」は, 下部ナビゲーションと同じ働きなのでスマホでは出しません. タブレットでは従来どおり出します.
- Writing Mode はスマホでは使えないため, 切り替えのボタン (共通ヘッダーにある) ごと出しません. 幅を変えてスマホの幅になったときも, Writing Mode の画面ではなく通常の画面 (`mobilePane`) で表示します. 代わりの「開いているタブ」は下部ナビゲーションの右端です.

### 下部ナビゲーション (5項目)

左から順に:

1. **トレイ** (Inboxのアイコン): Tray一覧 (`trays`) を表示します.
2. **メモ** (一覧のアイコン): 今のTrayのメモ一覧 (`notes`) を表示します.
3. **検索**: 全体検索を開きます.
4. **新規** (ペンのアイコン): メモ一覧へ移り, 「メモを追加」の入力欄を開きます (キーボードが出ます). 作成の規則は従来どおりです (Enterで作成, 一覧と選択を保ち, 作ったメモは選んだときに開く). すべてのメモでは上の追加先へ, 復元を表示しているときは追加先のTrayへ移ってから開きます. Trayが1つもないときは押せません.
5. **タブ** (右端, Glesさんの指定): 開いているメモの一覧を下から開きます. 件数を小さな数字で示します. 項目を押すとそのメモをエディタで開き, ×で閉じます. 開いているメモがないときはその旨を出します. 最後のタブを閉じたときにエディタを表示していれば, メモ一覧へ戻ります.

- 今の画面の項目を強調します (`aria-current="page"`). エディタを表示しているときは「タブ」を強調します.
- 各項目はアイコンと短い名前 (11言語) で, 押せる大きさは高さ56px・幅は5等分 (390pxで約78px) です. 名前が長い言語は1行で省略します.
- 「設定」「アカウント」「言語」は使う頻度が低いため, 項目にせずTray一覧の見出しに置きます (Tray一覧をアプリの入口の画面として扱う). 「新規」は書き留めの頻度が高いため項目にしました.

### 状態と本文の読み込み

- 新しい端末で本文がそろうまで (`bodyProgress`がある間), 下部ナビゲーションの上に細い帯を出し, 「本文を読み込み中 (120 / 562)」と進み具合のバーを表示します (`role="status"`). どの画面でも見えます.
- 保存状態のアイコン (保存済み・保存中・失敗) はTray一覧の見出しのアカウントの横です. 一覧やエディタの画面から失敗に気づける表示は今回は入れていません (残りの課題).

### 安全領域 (ノッチ・ホームインジケーター)

- `/app/`と`/playground/`は`viewport-fit=cover`にし, 安全領域を自分で空けます: 画面全体に上・左・右の`env(safe-area-inset-*)`, 下部ナビゲーションに下の`env(safe-area-inset-bottom)`. 下部ナビゲーションのない幅 (タブレット等) では画面全体の下に空けます. Landing-page等は従来どおりです (`viewport-fit`を変えない).
- 画面の高さは`100dvh`にします (`100vh`はiOSのSafariで下のツールバーの裏まで伸び, 下部ナビゲーションが隠れるため). 対応ブラウザー (Safari 16.4以降, Chrome 111以降) はすべて`dvh`に対応しています.

### キーボード

- 文字の入力中 (入力欄・エディタにフォーカスがあり, 画面のキーボードで表示領域が120px以上狭くなっているとき) は, 下部ナビゲーションと状態の帯を隠し, 書く場所を広くします. キーボードを閉じると戻ります.
- フォーカスだけでは判断しません (Androidの戻るキーはフォーカスを残したままキーボードを閉じるため). 拡大表示 (ピンチ) は`visualViewport.scale`で除きます.

### 一覧の端への移動

- スマホではリストスタイルをTray一覧の見出し (設定) で変えるため, メモ一覧は隠れています. 隠れている間に求められた端への移動 (リストスタイルの切り替え) は, メモ一覧を表示したときに行います. エディタ等から一覧へ戻っただけのときは, 読んでいた位置を保ちます (AGENTS.mdのMemo Scrollの「一覧を開いたとき・切り替えたとき・自分で追加したときだけ」を, 1画面ずつのスマホでも守るため).

### タブレット・PC

- 共通の変更 (1〜4) 以外は変えません. タブレットのTrayの引き出し, 戻る・トレイを開くボタン, Writing Mode, PCの3カラムと比率は従来どおりです.

## 検討した他の案

- 下部ナビゲーションの4番目を「設定」にする案: 設定は使う頻度が低く, 書き留めの「新規」を優先しました.
- 「その他」にアカウント・言語・設定をまとめる案: 1回多く押すことになり, Tray一覧の見出しに空きがあるため採りませんでした.
- 「新規」で無題のメモをすぐ作ってエディタを開く案: 作成の規則 (入力欄で確定・選ぶまで開かない) と変わるため, 入力欄を開く形にしました. 変えるときは規則 (AGENTS.mdのCreation) から見直します.
- エディタの書式ツールをキーボードの上へ移す案: `visualViewport`に合わせた配置が必要で, 今回は見送りました (残りの課題).

## 実装

- `src/components/mobile-nav.tsx`: 下部ナビゲーション, 開いているタブの一覧, 状態の帯, キーボードの判定 (`useKeyboardOpen`).
- `src/components/workspace-view.tsx`: スマホでは共通ヘッダーを出さず, 各画面の見出しと下部ナビゲーションを描きます. Writing Mode はスマホでは`home`として扱います. ピン留めの囲み, チャットスタイルの追加欄の位置, すべてのメモの追加先.
- `src/components/memo-actions.tsx`: エディタのメモの操作 (ピン・履歴・削除). `tiptap-editor.tsx`はツールバーの右端に置き, タイトル行の履歴・削除の絶対配置をやめます.
- `src/components/inline-name-editor.tsx`: 「新規」から入力欄を開くため, `InlineCreate`に`ref`で`open()`を足します.
- `src/lib/mobile-copy.ts`: 新しい文言 (11言語).
- `src/app/app/layout.tsx`・`src/app/playground/layout.tsx`: `viewport-fit=cover`.
- `src/app/globals.css`: 安全領域, `100dvh`, ピン留めの囲み, メモの操作, 下部ナビゲーション.

## 検証

- 単体: 新しい文言が11言語でそろい英語のままでないこと, すべてのメモの追加先の規則.
- 画面 (Playground, 開発Server): 390px (タッチ) と1440pxで, ToDo・チャットの両スタイル, ライト・ダーク. 下部ナビゲーションの5項目, タブの一覧の切り替えと閉じる, 「新規」で入力欄が開くこと, Writing Mode がスマホで出ないこと, メモの操作 (ピンが一覧と連動), ピン留めの背景, 追加欄の位置, すべてのメモでの追加. タブレット (1024px) で引き出しとWriting Mode が従来どおりであること.

## 残りの課題

- 保存の失敗を一覧・エディタの画面からも気づけるようにする (保存状態を`WorkspaceView`へ渡す. `cloud-session.tsx`の変更と合わせて行う).
- タブレット (768〜1279px) も状態の文字が隠れる (アイコンのみ). 同じ帯を出すか検討します.
- エディタの書式ツールをキーボードの上に出す (スマホ).
- iOSでキーボードを出したときに画面全体が持ち上がる動き (従来から) の調整.
